ASTRA · DIRECT ROBOT CONTROL · IMPLEMENTATION GUIDE

Agent-legible hardware

How the same Astra actor controls LIBERO’s fixed-base Panda and RoboCasa’s mobile PandaOmron through F, B0, B and F-adaptive. The device abstraction describes the native controller; it does not convert an abstract task into a motion plan.

Recorded F / F-adaptive before-and-after example: exact code, revisions and videos

F · typed interface

Explicit channel semantics, units, frames, bounds and command metadata. The model still chooses every native action.

F-adaptive · evolving interface

F plus tools Astra can write and revise, optional hardware information, and measured calibration. Every episode starts fresh.

B0 · native tools

Observe native keys and submit the native controller vector. The model discovers the conventions through shared audited source.

B · native + observer

B0’s interface plus a separate stateless Astra observer. Its current-image descriptions contain evidence and uncertainty, with no action tools.

These diagrams describe the implemented interfaces. Benchmark results are reported separately. All four actors can receive images directly. F-adaptive combines tool evolution with optional extra hardware information; this comparison does not isolate those two effects.

One live control cycle

01

Prepare

Worker loads frozen task / seed / arm, verifies source and runtime, resets the native environment and records its controller and initial-state identity.

02

Discover

F receives hardware-1 JSON; describe_device can refresh it. B0/B inspect audited source to discover native keys, action order, scaling and frames.

03

Sense

F read/read_latest or B0/B observe samples paused current sensors. JSON carries the current simulator step. PNG images become model image inputs.

04

Reason

provider.Session sends the task, history, tools and observations to Astra. Physics is paused. Weights stay fixed; scratch is optional.

05

Validate

Router validates allowed tools and strict JSON; Proxy validates finite numbers, exact vector length, controller bounds, repeat count and freshness. F also checks channel, mode, units and episode.

06

Execute

Proxy.step applies the same native vector for the requested repeats, at most ten. The adapter advances physics; private official success is checked after each native step. First success stops the remaining repeats.

07

Observe again

Actor receives an execution receipt, never reward/done/info or the private success label. It reads current sensors and submits a fresh observation_step for the next action. episode_ended signals termination.

08

Verify

Worker records outcome and terminal state. Independent replay reconstructs the reset and saved actions in another process, compares first success and terminal state, then archives evidence. No model calls in replay.

Success is checked inside each repeated command. For example, a requested 10-step action can return applied_steps=4 when success occurs on its fourth native step. F and B0/B share this exact behavior.

How Astra evolves its harness

The editable harness is a versioned layer of tools, enabled capabilities and notes above the native robot API. The model chooses how to use it during the episode.

Inspect a real rollout: camera calibration, new control tools, and a triangulation-code revision at native step 211.

The top-level model tool schemas stay fixed. Newly written programs live in an episode-local registry and are invoked by name through call_interface_tool; the model receives their descriptions, version hashes and current interface notes.

Available hardware informationDiscover and enable allowlisted additional encoders or camera calibration, when the adapter supplies them.

Measured response model or operating notesProbe a bounded native command, inspect before/after readings, and retain a hypothesis in per-episode notes.
Interface versionRestore earlier capabilities, tool definitions and notes. Robot motion and consumed steps remain.

Fixed underneath: model weights, native controller, execution checks and private success evaluator. No tool or learned notes transfer into the next trial. Probe actions and control tools use the same episode horizon.
