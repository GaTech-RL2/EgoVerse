## Installation
Currently only usable with everse uv environment. Inside everse uv environment, 
```
cd external/openpi
uv pip install -e .
```
Replace the default transformers module inside your environment with the custom version:
```
cp -r ./src/openpi/models_pytorch/transformers_replace/* <path_to_your_uv_env>/lib/python3.11/site-packages/transformers/
```

## Getting pretrained checkpoint
From EgoVerse directory
```
mkdir egomimic/algo/pi_checkpoints
uv pip install gsutil
gsutil -m cp -r gs://openpi-assets/checkpoints/pi05_base egomimic/algo/pi_checkpoints/
```

Convert JAX checkpoint into Pytorch
```
cd external/openpi
uv run --active examples/convert_jax_model_to_pytorch.py \
  --config_name pi05_aloha \
  --checkpoint_dir ../../egomimic/algo/pi_checkpoints/pi05_base \
  --output_path ../../egomimic/algo/pi_checkpoints/pi05_base_pytorch
```

## Starting from PaliGemma instead of the pi0.5 base

`model/pi0.5_paligemma_init.yaml` is an overlay that swaps the pi0.5 base
checkpoint for the public PaliGemma release: the VLM prefix (SigLIP tower,
multimodal projector, Gemma-2B) is loaded from `paligemma-3b-pt-224`, and
everything pi0.5 adds on top — the 300M action expert, the action in/out
projections, the adaRMS time MLPs — trains from scratch. That is the ablation
that separates "what the VLM knows" from "what pi0.5's robot pretraining added".

A ready-made arm ships for the mecka 6D configs:

```bash
python egomimic/trainHydra.py --config-name=train_zarr_cartesian_pi \
    data=mecka_fold_freeform_opscale1_6d \
    model=pi0.5_bc_mecka_6d_paligemma_init \
    evaluator=eval_pi_wristframe_6d
```

Layer the overlay onto any other `pi0.5_*` config the same way (`defaults:
[pi0.5_bc_aria, pi0.5_paligemma_init, _self_]`), or set the two keys per run:

```bash
model.robomimic_model.config.pytorch_weight_path=null \
model.robomimic_model.config.paligemma_weight_path=google/paligemma-3b-pt-224
```

Setting both paths raises: the pi0.5 base checkpoint already contains a trained
PaliGemma, so letting one silently win would make a run's provenance
unreadable from its config.

### Getting the weights

`google/paligemma-3b-pt-224` is license-gated. Either authenticate

```bash
huggingface-cli login   # with a token that has accepted the Gemma terms
```

or set `paligemma_allow_mirror: true` to let `egomimic/models/paligemma_init.py`
fall back to a third-party mirror on a 401/403 — it compares every shard's
sha256 against the canonical repo's file metadata (readable without a token)
before using it, so a mirror is transport only and cannot substitute different
weights. It is off by default so the weights of record come from the canonical
repo. `$EGOVERSE_PALIGEMMA_WEIGHTS` points the arm at a local snapshot
directory and skips the Hub entirely.

Pre-fetch once before a multi-rank run, or every rank races on the same
download lock:

```bash
python -c "from egomimic.models.paligemma_init import resolve_paligemma_dir as r; print(r('google/paligemma-3b-pt-224'))"
```

### What the loader checks

The released checkpoint does not drop in unchanged, so the load is strict about
the two places it differs and fails loudly anywhere else:

- the checkpoint's `vision_tower.vision_model.*` keeps its `vision_model.` hop
  below transformers 5 and loses it from 5 on (`SiglipVisionModel` was
  flattened); the loader maps onto whichever the model has.
- the release pads the token embedding from PaliGemma's 257152-token vocabulary
  to 257216 rows (`<image>` plus 63 unused). openpi builds the table at exactly
  257152, so `embed_tokens` / `lm_head` are truncated on their vocabulary axis;
  the padding is at the end, so every real text token keeps its row.

Any parameter the checkpoint does not cover, and any checkpoint tensor with no
home in the module tree, raises — a partial load that quietly leaves half the
VLM random is the failure mode this exists to prevent.

### Hyperparameters

The overlay changes the init source and nothing else: the optimizer stays
`pi0.5_base`'s fine-tuning recipe (constant 3e-5 after 2000 warmup steps). A
randomly initialized action expert may want a higher peak and a longer warmup —
that is a per-run decision, e.g.

```bash
model.optimizer.lr=1e-4 model.scheduler.num_warmup_steps=5000
```

## transformers 4.53 vs 5.x

`external/openpi` pins `transformers==4.53.2` and its `transformers_replace`
patch is written against that version (`models/siglip/check.py` asserts it).
So does `pyproject.toml`, and the install steps copy that patch into the venv:
4.53.2 plus the patch is the supported setup, what CI installs and what the
shared `emimic` venv carries. Which transformers a run gets is whatever its venv
has, so check before comparing numbers across machines.

A venv on transformers 5.x (the PaliGemma-init arm was first run on 5.17 with a
partial hand-port of the patch: the Gemma modules carry openpi's adaRMS changes,
but `modeling_paligemma.py` and `modeling_siglip.py` are effectively stock 5.x)
also works, but three of openpi's assumptions do not survive it:

- `PaliGemmaModel.get_image_features` now returns a `BaseModelOutputWithPooling`
  with the projected features on `pooler_output`; openpi's `embed_prefix` reads
  `.shape` off the result.
- transformers 5 dropped the back-compat properties that forwarded
  `PaliGemmaForConditionalGeneration.language_model` / `.vision_tower` /
  `.multi_modal_projector` to the inner `PaliGemmaModel`; openpi reads all three
  off the outer model.
- openpi's float32 keep-list names the SigLIP patch and position embeddings
  `vision_tower.vision_model.embeddings.*`; with `SiglipVisionModel` flattened
  nothing matches and they would train in bf16.

`egomimic/models/openpi_compat.py` bridges all three, applied from
`egomimic.algo.pi`. Each shim is guarded on what it finds and stands down
entirely below transformers 5, so porting the fork's patch forward makes the
module a no-op — delete it then.

On 5.x only the PaliGemma-init arm loads. The pi0.5 base checkpoint
(`pi05_base_pytorch/model.safetensors`) stores the nested
`vision_tower.vision_model.*` names and `safetensors.torch.load_model` is
strict, so the default init path stops at startup on missing SigLIP keys.
Train from the pi0.5 base on the pinned 4.53.2.
