# Offline learned correction: protocol review and report contract

This is a proposed, authorized follow-up using recorded teacher experience. **No training or evaluation result is reported here.** The new experiment makes no Astra calls. It tests whether a small selector or flow-output correction can retain useful behavior without the remote teacher. The [configuration](../../configs/learned_correction_recipe_v1.json) and frozen runtime supply exact implementation settings and artifact hashes; this review does not replace them.

The source studies and their costs remain separate. The [completed phase-interpolation cohort](../phase_interpolation/evaluation/results/report.json) supplies ten successful Astra text-intervention trajectories: four TEI and six TLI, with 1,030 executed actions and 211 five-action replans across seven compositions. The [interrupted representation pilot](../representation_steering/development/results/report.json) adds the individually archive/provider-verified wine TEI success (98 actions) and milk TLI success (120 actions), adding 44 replans and one composition. Thus the prescribed text-teacher set has **12 trajectories, 1,248 executed actions and 255 replan windows across eight known compositions**. These windows are correlated observations, not 255 independent demonstrations. The two pilot source cases have verified partial archives rather than final complete-case seals; that provenance distinction must remain visible in the corpus manifest.

## Fixed five-arm comparison

| Arm | Decision mechanism | Policy conditioning and correction | What its comparison tests |
|---|---|---|---|
| `native` | No learned intervention | Original task, raw cameras/proprioception, frozen native policy | Common paired reference |
| `recorded_schedule` | Task prompt and absolute executed-action step | Replays one prescribed successful teacher's TEI/TLI source pair and coefficient | How much a memorized successful schedule explains |
| `learned_selector` | Frozen native visual/text features and raw proprioception; no elapsed-step input | Predicted TEI/TLI class and coefficient, or native | Observation-based selection versus the recorded schedule |
| `flow_head` | Learned small native-flow output-head correction | Original native task/camera conditioning; no TEI/TLI | Action-learning effect without representation assistance |
| `gated_flow_head` | Same flow head, enabled only when the selector's intervention score is strictly greater than 0.5 | Original native conditioning throughout; no TEI/TLI, including when enabled | Effect of a learned support/selection gate on the identical correction |

The threshold is fixed before evaluation: a score of exactly 0.5 selects native. It is an **imitation/support score, not a calibrated probability of native failure or a causal estimate of intervention benefit**. The gated arm must load the same learned head as `flow_head` and the same selector as `learned_selector`; no per-arm refitting. When the gate is off, use the exact native vector field and matched noise. This is not a composite TEI/TLI-plus-head arm.

For each task prompt, the schedule chooses a successful teacher deterministically: phase seed-29 TLI first, then phase TEI, then the pilot text teachers; within an arm, lower revision precedes lexicographic episode ID. The input manifest resolves every tie before training/evaluation. It does not choose the shortest or best evaluation rollout. Apply the nearest preceding recorded teacher decision at the absolute action step; after the teacher's final decision, hold that choice through the evaluation budget. A task without a text teacher stays native under this arm. This extrapolation past the teacher's successful endpoint is an explicit limitation of the control.

Intervention classes retain operator and source-pair identity. Canonicalize a source pair lexicographically and complement alpha when swapping its order, preserving the exact TEI/TLI operator. Regress alpha only within the chosen class. TEI alpha zero selects source A; it is not a native fallback. TLI alpha 0.5 is neutral. Native and neutral choices must be identified from the actual executed condition, not inferred merely from a successful API call.

## Training and evaluation split

Training uses all twelve prescribed successful text teachers plus seven successful seed-29 native baseline anchors (774 actions, 158 replan windows). This gives **19 historical trajectories, 2,022 executed actions and 413 windows** before new anchor collection. The exact deduplicated physical records are fixed in the training manifest. Four new native anchor-collection rollouts use the original pinned standard LIBERO10 tasks 0, 1, 2 and 3 at prescribed reset index 0, with its 520-action preset. Only successful collection rollouts enter the positive native-anchor set. Their failures and full acquisition costs still remain in the record. No evaluation outcome selects an anchor, checkpoint, threshold, teacher or schedule.

Selector features come exclusively from the **raw native condition**: mean valid visual slots and mean valid instruction/text slots at the last prefix layer, plus the raw eight-dimensional robot state. Decisions refresh every 25 executed actions and policy replans execute five actions. Do not extract features after a teacher TEI/TLI intervention, which would leak the target label. Do not supply elapsed step, future outcome, normalized eventual trajectory progress, simulator object poses or a hidden success predicate. The original instruction is legitimate input, so the model can still identify familiar task compositions; the schedule control measures part of that shortcut.

The configured selector uses hidden widths 128 and 64, 1,000 updates, batch size 64, learning rate 0.001 and weight decay 0.0001. The configured correction has 7,175 trainable parameters, a residual bound of 0.5, 1,000 updates, batch size 128, learning rate 0.0001, anchor weight 1, L2 weight 0.0001 and gradient clipping at 1. Eight flow-training draws per window provide noise/time augmentation, not eight independent demonstrations. Unexecuted physical rows use a new original-condition native sample, and clean padded dimensions are zero: this is declared bridge imputation, never supervision. These are frozen settings, not measured optimization results or tuned recommendations.

| Evaluation cohort | Prescribed cases | Per-rollout cap | Physical rollouts |
|---|---|---:|---:|
| Both LIBERO-OOD suites | All 20 compositions; seed 61 reset-stream indexes 1 and 2 | 300 actions | 20 × 2 × 5 = 200 |
| Standard LIBERO10 retention panel | Task IDs 0, 1, 2 and 3; prescribed reset indexes 1 and 2 | 520 actions | 4 × 2 × 5 = 40 |

There are **48 distinct reset cases and 240 evaluation rollouts**. All five arms run unconditionally on every case, including cases where native succeeds; there are no success-gated skips, retries, best-of-attempts scores or evaluation-time learning. Policy noise is keyed identically across methods for the same case and replan step. Each method has its own resulting observation trajectory. Use native Euler10 and execute five actions per replan, with exact paired reset-state, model-geometry and observation hashes.

The standard retention panel covers **4 of 10 LIBERO10 tasks**, not the entire ID benchmark. Checkpoint training overlap is not independently established by calling a task standard LIBERO. OOD evaluation measures new resets of known compositions, not new-task generalization. Report the eight teacher-covered compositions (Goal 1, 5, 6, 7; Spatial 2, 5, 8, 9) separately from the other twelve, while retaining all twenty in the primary OOD denominator. OOD seed-stream indexes and standard suite's prescribed state indexes are different reset mechanisms and must not be conflated.

The deployment budget is five L40S evaluation workers: four OOD workers and one standard-panel worker, after one GPU completes extraction/training. The cap is 80,800 evaluation actions and 161,600 Euler vector-field evaluations before separately counted parity/probe work; four anchor-collection rollouts add at most 2,080 actions and 4,160 evaluations. These are **planned maxima, not measured cost**. Training updates, feature extraction passes, cache bytes and optimizer settings must be frozen and measured separately; no hyperparameter sweep or evaluation-based checkpoint choice is implied.

## Risks and required integrity checks

- **Selection labels are not counterfactual gate labels.** Successful teacher windows and successful native anchors do not reveal whether a particular state needs help. Both distributions are outcome-selected, and the score may recognize task or trajectory identity. Report activation frequency and paired harms as well as rescues; do not attach failure-probability or calibration language to the threshold.
- **Use actually executed windows.** A generation predicts a longer chunk but normally executes only its first five commands; the final window can be shorter. Supervise only `min(5, remaining_executed_actions) × 7` controller dimensions, with their exact checkpoint normalization, state and clipping provenance. Never call an unexecuted suffix or padded dimensions a demonstrated action. The training bridge/tail-fill rule and any preservation loss must be explicit; masking a loss alone does not specify how unobserved action slots enter the frozen flow model.
- **Use the applied teacher program.** A rejected refresh can leave a prior text edit active in the older phase protocol, whereas the newer pilot clears failed choices. Reconstruct labels from generation/application provenance, including the applicable hold rule, rather than the latest request or proposed program. Only the prescribed successful text trajectories enter the correction corpus; unfinished or quota-fallback outcomes are not positive teacher evidence.
- **Avoid accidental duplicate evidence.** Shared baselines appear in multiple arm summaries and must contribute once. Closely matching recovered/known-noise native controls are not independent demonstrations; preserve physical IDs and inspect exact observation/action duplicates. Balance or explicitly report trajectory/task weighting so a long or frequently sampled teacher does not silently define the objective.
- **Keep the native policy frozen.** Bind the base checkpoint, processor, normalization, text banks and operator source. Zero correction and disabled gate must reproduce native outputs under the same noise. Limit updates to the declared selector/head parameters; save initial/final parameter inventories and optimizer state. Native action decoding and controller bounds remain unchanged.
- **Check feature and class equivalence.** Exclude padding and noninstruction special slots from text pooling; preserve camera order. Mean pooling may alias distinct grasp/placement phases and is a model limitation. Canonical source-pair swaps must preserve operator outputs; labels with different source pairs must not be merged by averaging alpha.
- **Prevent split leakage.** Hash the training manifest before reading evaluation outcomes. Keep complete episodes together; frame-level train/validation splits are not independent validation. All twelve teachers are prescribed training data, so loss measured on those same trajectories is training fit, not held-out performance. Any additional diagnostic validation split must be declared before it influences fitting.
- **Report executed harm and bounded failures.** Preserve every method/reset result, initial-success flags, runtime failures, clipping and intervention activation. Initially successful resets are invalid for improvement credit and require review without silently dropping them. A capped unsuccessful rollout is a failure/censored time-to-success observation, not a missing case. Repair rules must be outcome-independent.

## Report contract

[report_schema.json](report_schema.json) specifies the proposed machine report shape. It is a schema, not an example result. A producer must independently enforce the semantic invariants below, in addition to JSON-schema validation.

1. Exactly 240 unique physical evaluation rows cover the Cartesian product of the 48 prescribed cases and five arms. Every complete-case audit binds summary/events/actions, reset hashes, checkpoint hashes and runtime/protocol identity. No efficacy table is released before coverage and integrity are complete; partial costs remain available with their scope.
2. Keep OOD outcomes and the standard retention panel in separate primary tables. Within OOD, show teacher-covered and other-composition strata. Include per-task, per-reset, per-method outcomes; there is no pooled historical or development denominator.
3. For every arm versus native, report both-success, arm-only-success, native-only-success and both-failure counts and discordant episode IDs. Also compare selector versus schedule and gated versus ungated head. Rescues are conditional on native failure; harms are conditional on native success. Show both denominators explicitly.
4. Report success within the one fixed rollout cap, executed actions and capped failures. Report actions-to-success only among successes, alongside the censored count. Training-update indices and selector decisions are not intervention attempts; no historical revision-budget curve is reused as a learning curve.
5. Separate anchor acquisition, offline extraction, optimization, evaluation and audit/publication costs. Count physical baseline rollouts once. Preserve wall time, GPU-active measurements if available, prefix passes, vector-field calls, optimizer updates, cache sizes and missing measurements. Zero new provider calls does not make historical teacher acquisition free: link exact source-study costs and state whether selected-trajectory costs or whole-cohort acquisition costs are being attributed.
6. Save checkpoint and corpus hashes with each result; report gate activations, actual corrected actions and zero/native decisions. A changed action or lower training loss is an implementation/fit observation, not evidence of successful control.
7. Render static, portable HTML/Markdown/CSV and plots only from measured rows. Figures bind their exact plotted values and report/source hashes. Use task-paired analysis; with only two resets per task, repeated windows or five methods do not create independent task replicates. Any uncertainty calculation must respect task clustering and disclose the small panel.

The decisive first result is whether either learned mechanism improves new-reset OOD outcomes while limiting paired damage to native successes and the standard retention panel. A negative or mixed result remains informative. No calibrated gate, autonomous generalization, cost saving or learned improvement is established by this design document.
