# PEAR Cartesian interface transition — 19 November 2026

The user approved end-effector control for the PEAR RL run, then explicitly
restricted the change to RL. The separate Astra collection keeps its original
action spaces, prompts, exact Astra 6.2/xhigh profile and token limits. No EEF
teacher calls or EEF SFT examples were produced.

## Motivation and scope

The early-RL diagnostic sample contained 133 joint-bound rejections among 168
closed native YAM attempts. Other reviewed trajectories described Cartesian
movement without producing the corresponding object interaction. RoboDojo
also rejected an `ee_pose` request because the active contract permitted joints
while the full public SDK advertised poses. These motivate the interface
ablation; they do not establish that an EEF policy will improve task success.

The new `pear-eef-native-v1` branch retains native simulator coordinate frames,
RGB, robot proprioception and native graders. The model chooses goals; robot-only
controllers translate them into ordinary joint actions. There are no object
poses, task skills, grasp planners, pose writes or replacement success rewards.

| Simulator | Cartesian path |
|---|---|
| Native GR00T YAM | Bounded Jacobian IK using the existing native teleoperation math |
| RoboDojo, RoboLab, EFE YAMLab | Existing native pose controller, capped by requested native steps |
| ABC-Sim | Public robot-only IK, followed by bounded native joint interpolation |
| VLABench | Native robot-only IK in an owned simulator-source overlay |
| DexJoCo | Native operational-space pose controller, retaining Allegro finger targets |
| LIBERO-Max, MetaWorldPlus, RoboCasa | Existing native Cartesian deltas; preserve auxiliary base/torso controls |

Pose actions retain explicit quaternion ordering and tool origins. Parallel
grippers use 0 open / 1 closed with a declared conversion to native units.
Cartesian-delta environments keep their existing documented native scaling.
The eight procedural reasoning families retain their existing answer types.

## Implementation and measured diagnostics

The new configuration is opt-in. Legacy prompt fixtures were compared against
HEAD and remained byte-identical. Live Astra worker specifications were separately
checked to retain their existing interfaces. RL worker reuse now excludes current
teacher-owned allocations, preventing the new run from replacing those jobs.

Native pose waypoint loops previously ignored `dt` and could execute more than
the JSON `repeat` count. The opt-in RCB wrapper now interprets repeated identical
pose rows as a maximum native step budget, intercepts the original step function,
and returns exact counts and native tracking feedback. The native controller,
recording and success checks remain in use.

Discarded model-free probes, kept under `artifacts/embodied-first-exam/pear-scaled-v1/eef-interface-v1/`:

  cap. The revision uses explicit position/rotation feedback gains 3/2 and the
  native bounded error and joint-increment limits.
- Native YAM v2: 11/12 passed; +Z moved 1.70–1.72 cm for a 2 cm request. Gripper
  closure measured about 98%, reopening and exact budgets passed. One forward
  check had 15.35 mm orthogonal drift against a 15 mm threshold.
- Native YAM v3: 11/14 passed, including both +Z checks. Added negative-X checks

  failures remain failures; initial-pose six-dimensional reachability is under

  checks in two training scenes. Its preparation actions are discarded and are

- RoboDojo: 12/12 native checks passed across two admitted training tasks.
- RoboLab and EFE YAMLab: 6/6 native checks passed in each suite.

The complete qualification composes passed per-suite receipts, checks current

The Dex-specific declaration change was measured by its current native probe.
No EEF optimizer update, held-out improvement or complete EEF checkpoint is
claimed by these checks.

## Infrastructure findings

One discarded RTX bootstrap failed because a copied old `bootstrap.py` was
accidentally included in its replacement archive. Extraction tried to overwrite
the scheduler's read-only bootstrap mount. Excluding that file and compiling
source before submission fixed the packaging path. No policy action executed in
that failed bootstrap; no allocation was canceled.

An L40 fallback for the nested-container core probe was rejected because that
platform forbids privileged tasks. A partial H100 fallback was rejected because
its platform requires eight GPUs. Those unsupported launch options were removed;
the original eight-H100 job subsequently started. OSMO reported 40 free H100s on
`h100-02`, while the matching HIGH request was on `h100-01` and the request on
02 required 56. A matching 40-H100 HIGH request on 02 obtained all five nodes.
The 56-H100 LOW standby and all live allocations remain retained.

VLABench's Dockerfile copies its service from a pinned files image after the
local build context, so changing a checked-out template did not change the live
service. The owned overlay now copies the adapted service last. A native motion
then exposed a NumPy boolean in new feedback; converting it to a Python bool
fixed serialization. Native positive/negative grading and instance files remain
unchanged. Two model-free probe attempts also encountered Harbor's native
network-policy startup failure; these remain infrastructure errors, never reward 0.

An exec timeout into one retained renderer allocation delayed independent
worker provisioning. Native requests now use stable job IDs so lost
acknowledgements cannot repeatedly restart a healthy child. For qualified
AMLFS07 controls, the owning model trainer can stage and checksum the same
request on the shared filesystem after both allocations pass their scheduler
barriers. Other simulator families continue provisioning when one connection
is deferred. None of these recoveries cancels an allocation or changes the RL recipe.

## Training and checkpoint provenance

The planned EEF branch starts from the original Qwen3.6-35B-A3B MoE warmstart496
with a fresh optimizer and a distinct `rp_jhh_..._eef_...` directory. It preserves
32 usable groups × 8 trajectories/update, the 160k episode budget, frozen routers,
SGS, score centering and the current task-signal curriculum. The old run's four
actor updates remain separate: its step-4 full checkpoint was never committed,
and optimizer ranks 6/7 were incomplete. This is not an exact continuation.

The new job is `eef-runtime-00d2e3111b86` in allocation
`rp-jhh-pear-eef-capacity-40-p02-v1-1`, with run directory
`rp_jhh_pear_moe_warmstart496_eef_416a7560526c`. Its Ray runtime started during
validation; a source-pinned release prevented policy rollouts and gradients
until all ten simulator interfaces qualified. The driver is now released.
Pre-update runtime attempts have distinct records and no optimizer history.
Source hashes enter the interface/run identity so an older pending worker cannot
serve a repaired interface's transport. The full mixture remains 225 native
control tasks, 16 YAM graphs / 1024 independent resets and 512 scenes across eight
procedural reasoning families.

The model allocation uses 8 trainer and 32 inference H100s. The retained
8-H100 validation allocation was reused as another identical native
simulator replica, alongside the existing 8-H100 simulator allocation and
separate RTX workers. This changes throughput capacity, not group size or sampling.

Checkpoint publication and reload need to remain truthful: temporary node-local
files or partially uploaded shards are not durable checkpoints. Retain all
allocations across failures; stage and verify replacement children before use.
