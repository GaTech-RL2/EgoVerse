Research protocol: EFE direct-control v1

Solve the task through a repeated observe–act–check cycle using the documented public robot client. All benchmark rules, limits, camera access and grading still apply. Do not access simulator internals, oracle policies or hidden success state.

Use exec_command to run short, self-contained Python snippets. Import Robot from rcb_client, construct Robot(), inspect spec(), and obtain get_obs(). The task instruction documents the API; do not invent methods or command-line wrappers. Print the relevant public specification and current proprioception. Save observations with result.save('/app/runs/UNIQUE_STEP') and use view_image on the saved current image paths. Inspect the returned observations before deciding the next motion.

For each action, choose an explicit small array of native actions from the current observation and public specification. Submit it with Robot.submit using the actual action name, dimensions, bounds and control_dt. At most one submit per exec_command, at most 128 action rows and at most two seconds of simulated motion per submit. A repeated constant action or a short explicit sequence is allowed. Do not write a feedback controller, helper command-line program, background process or interactive Python session. Do not package a complete task solution into a long loop. Each new action block should be chosen by you after inspecting the result of the previous block. The action duration limits also apply to get_obs(seconds=...) holds.

Use exec_command with yield_time_ms=30000 for these short commands. Do not use apply_patch, search for patch binaries, or execute rcb_client.py/rcb1.py as programs. Do not use write_stdin; if a returned command is unexpectedly still running, report the problem rather than inventing or repeatedly polling a process ID. Keep the existing benchmark-required /app/output/gen.py as a record of the snippets actually executed; it is not a reusable controller or a privileged solution.

Before each motion block, give a brief public decision summary (up to 120 words): the visible or proprioceptive evidence you are using, the intended motion, and what observable result would lead you to adjust. This summary is an explicit training annotation, not a request for private reasoning. After a tool error, fix the specific error using the returned feedback; do not repeat an unchanged failed command. Stop submitting when the observed final state satisfies the task instructions. The independent verifier determines success.
